## 0. 设计目标

解决菜园子现有玩法"不好玩"的结构性问题：

1. **没有决策**：作物性价比单调递增，解锁贵的就永远不种便宜的 → 需要权衡与风险
2. **惩罚是纯损失**：专注中断清空所有作物，纯挫败无戏剧性 → 需要"复仇目标"
3. **金币没有长期出口** → 需要消耗型欲望（后续迭代）
4. **"生长绑定专注"这个核心机制被浪费了** → 需要把专注变成策略资源

## 2. v1 已实现机制

### 2.1 专注连击（Focus Combo）

**设计意图**：把"专注"从倒计时变成策略资源。连续完成番茄钟可获得生长加速，中断则清零——玩家会为了加成安排学习节奏。

**规则**：
- 完成一个专注番茄钟 → `combo.count += 1`
- 专注中断/放弃 → `combo.count = 0`
- `combo.count >= 3` → 进入 `active` 状态，所有作物生长速度 ×1.5
- `combo.best` 记录历史最高连击（用于展示/后续成就）

**数据落点**（garden data 新增 `combo` 字段）：

```json
{
  "combo": {
    "count": 3,
    "best": 5,
    "active": true
  }
}
```

**触达入口**：新命令 `garden_record_focus(completed: bool)`。
- 计时器部门在**专注完成**时调用 `garden_record_focus(true)`
- 计时器部门在**专注中断/放弃**时调用 `garden_record_focus(false)`
- ⚠️ **待客户端部门确认**：当前计时器完成/中断的回调点在哪？需要接入此命令（见 §4）

**生长加成实现**：`garden_grow(minutes)` 在 `combo.active` 时进度按 `minutes × 1.5` 计算。

### 2.2 枯萎救援（Wilted Revive）

**设计意图**：惩罚不再"清空一切"，而是让作物进入**濒死**状态——玩家可以通过完成一个专注番茄钟救活它们。违规后的第一反应从"算了不玩了"变成"我要专注把它救回来"。

**规则**：
- 惩罚时：未成熟作物 → `wilted: true`（不再直接消失）
- 完成一个专注番茄钟 → 所有 `wilted` 作物复活（`wilted: false`，进度保留）
- 再次惩罚时：已 `wilted` 的作物 → **永久清除**（枯萎后又被罚就彻底没了，制造紧迫感）
- 已成熟作物不受惩罚影响（沿用原逻辑）

**数据落点**（plot 新增字段）：

```json
{
  "id": 0,
  "crop": "carrot",
  "progress": 10,
  "plantedAt": "...",
  "locked": false,
  "wilted": true
}
```

**触达入口**：与专注连击共用 `garden_record_focus(true)`——完成番茄钟即触发救援。惩罚沿用 `garden_punishment`。

## 4. 部门协调需求

### 4.1 给客户端部门（计时器模块）

> 日期：2026-08-08

菜园子 v1 新增 `garden_record_focus(completed: bool)` 命令，需要计时器在以下时机调用：

| 时机 | 参数 |
|------|------|
| 专注会话正常完成 | `completed: true` |
| 专注会话中断/放弃/违规重置 | `completed: false` |

该命令会更新连击数、触发枯萎救援、刷新成就。请确认接入点，或在合适位置调用 `useGardenStore().recordFocus(completed)`。

> 日期：2026-08-08

暂无需服务器变更。`combo` / `wilted` 字段仅在本地 garden data 持久化，不涉及云端同步。若后续做"菜园子排行榜/好友串门"（P2 迭代）会再协调。
