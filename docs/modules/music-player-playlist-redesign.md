## 0. 三个核心概念的关系（设计地基）

```
表（歌曲表）── 唯一的真实数据来源。每首歌一条记录（带字段）。
树（目录树）── 表的投影/视图。每个目录节点 = 一个查询条件（WHERE folder_path LIKE '前缀/%'）。
               树不存任何数据，实时从表派生。
播放列表（集合）── 对表的一次快照：树导航/标签筛选得到一批歌 → "推入"播放列表。
               独立的运行时状态，与树/表松耦合。
```

- **表是数据源**，**树是导航索引**，**播放列表是播放消费的候选集**；
- 树帮你"定位"表里的一部分歌；播放列表只是把"当前这部分歌"的引用记下来交给播放引擎；
- 三者不是同一个东西，**不耦合**。

## 1. 已确认设计决策（8 项，全部定稿）

1. **归属模型：唯一归属**。`folder_path` 为单值字符串，一首歌有且仅有一个目录归属；
   树的"一个文件一个位置"直觉保持，不产生重复条目；跨维度检索由多值标签承担，职责分离。
2. **多值标签**：标签升级为字符串数组，可叠加（风格/情绪/场景/主题/评分等）；
   查询支持"目录筛选 + 标签筛选"叠加。
3. **目录层级**：`/` 作路径分隔符（如 `导入/周杰伦/范特西`），子目录匹配 `前缀/%`。
4. **歌单快照：P2 再做**，P0 不承诺（先把"查询结果 → 集合 → 播放"链路跑通）。
5. **命名口径：统一用"目录"**，不用"文件夹"（避免唤起 OS 实树联想；文档/UI 统一）。
6. **排序字段：P0 只做"名称 + 来源"**；时长/添加时间/修改时间等排序放 P1。
7. **播放列表 = 集合（Set），不是序列（Queue）**：
   - 列表只负责"当前这批歌有哪些"，**不定义顺序、不展示顺序、无序号列**；
   - 顺序是播放引擎的职责：顺序模式 = 引擎按推入时的快照顺序迭代；随机模式 = 每次切歌现场随机抽（不需要事先生成"打乱序列"展示给用户）；
   - 用户看到的列表只有"集合里有哪几首"（含标签/目录/来源信息），没有"第 5 首是哪个"；
   - 清空集合 = 播放引擎停止（播完当前歌后停）。
8. **P0 范围锁定**（含最终交互模型修正——浏览与播放分离，KTV 式）：
   - **浏览区与播放列表（集合）完全解耦**：树/标签/搜索只是"找歌"的手段，浏览/预览永不改变集合；
   - 集合管理：单曲「+」加入 / 筛选结果一键全部加入 / 移除 / 清空集合；
   - 列表面板改版：宽度调整、搜索框、统计计数、目录树视图（筛选可折叠且默认收起）；
   - 标签筛选：多标签叠加筛选 + 计数；
   - 播放动作：**所有播放行为都发生在集合内**——「▶ 播放集合」「🔀 随机播放集合」（引擎切随机模式后从集合随机抽）；
   - 播放模式文案：随机 / 列表循环 / 单曲循环，语义明确；
   - 向后兼容：`tags.json` 扩展，现有播放器行为不变。

## 2. 数据模型

### 2.1 歌曲记录（`music/tags.json` 升级，向后兼容）

```jsonc
{
  "_customTags": { "白噪音": "#48dbfb" },
  "_v2": true,
  "歌名A.mp3": {
    "name": "歌名A - 番茄钟",
    "path": "导入/周杰伦/范特西",        // ★ 唯一归属（单值）；空 = 未分类
    "tags": ["学习", "白噪音"],           // ★ 多值标签
    "source": "builtin" | "download" | "p2p",   // 来源
    "addedAt": "2026-08-16T12:00:00Z",   // P1 用（P0 可仅落盘不参与排序）
    "duration": 213                      // P1 用
  }
}
```

- 兼容：旧记录只有 `{name, color}` → 读作 `tags:[name]`、`path:""`、`source:""`；老客户端照常读（忽略新字段）。

### 2.2 目录（树）的派生规则

- 目录**不落盘实体**：树节点 = `SELECT DISTINCT path 前缀` 实时投影；
- "未分类"= 空路径的特殊视图，不算实体目录；
- 目录重命名 `A/B → A/C`、删除 `A/B`、移动歌曲 = 字段批量更新（v2 文档 §1.2 保留此规则）。

### 2.3 播放列表（集合）的运行时表示

```ts
// store 运行时状态（不落盘，不跟随文件系统）
playList: {
  set: Set<string>,          // 歌曲引用（去重）
  snapshotOrder: string[],   // 引擎内部迭代顺序 = 推入时的查询结果顺序（仅引擎使用，UI 不显示序号）

}
playListSource: { kind: "all" | "dir" | "tag" | "mixed"; label?: string };  // 来源标注（如 目录·导入/周杰伦）
```

## 3. 特性需求清单

### P0（锁定）

| 编号 | 需求 | 功能层验收 |
|------|------|-----------|
| F1 | 歌曲表查询：名称搜索、多标签叠加筛选、目录（树节点）限定，可互相叠加 | 任一查询结果正确与实时 |
| F2 | 目录树（字段投影）：浏览、多级展开、节点计数、未分类视图 | 树始终与表一致，可折叠统计 |
| F3 | 目录管理：新建 / 重命名 / 删除 / **单首与批量移动** | 字段批量更新规则生效；删除目录不回误删歌曲 |
| F4 | 播放集合：把当前查询结果推入播放列表；清空集合 | 只有集合内歌曲被播；清空后引擎播完当前曲即停 |
| F5 | 播放动作（都在集合内）：「▶ 播放集合」「🔀 随机播放集合」；浏览/筛选永不改变集合 | 模式作用于集合 |
| F6 | 播放模式文案：随机 🔀 / 列表循环 🔁 / 单曲循环 🔂（`order`/`loop` 内部字符串不变，仅文案/图标） | 用户语义清晰 |
| F7 | 统计：当前查询结果总数、各标签计数、各目录计数 | 计数随筛选实时更新 |
| F8 | 目录自动归类（来源默认命名，见 §4.1） | 新歌落盘即入对应目录 |
| F9 | **移动交互舒适性**（核心）：单首/批量"从一个目录移到另一个目录"操作路径短、可见、可撤销入口（重命名/移动失败给出明确提示） | 用户无认知负担，误操作可恢复 |

### P1（排队）

- 排序：时长 / 添加时间 / 修改时间；
- 标签管理：重命名标签（同步所有记录）、合并标签、广播式清理；
- 来源快捷视图：最近下载 / 内置 / P2P 收到；
- 千首+级渲染性能优化（实现层）。

### P2（候选，不承诺）

- 歌单快照（命名持久化歌单，固化某次查询结果）；
- 空目录占位注册表、目录拖拽排序、播放统计（常听查询）。

## 4. 业务规则与边界

### 4.1 目录默认命名与自动归类（用户指定，落实为规则）

| 来源 | 默认目录 | 触发时机 |
|------|---------|---------|
| 内置歌曲 | `内置` | 扫描/记录首次创建时 |
| 榜单下载 | `下载` | 下载成功落盘时 |
| P2P 收到的歌 | `{用户名}传输`（如从 CC 用户收到 → `CC传输`；名字未知 → `未知用户传输`） | 接收合并完成时 |
| 手动放入 `music/` 的文件 | 未分类（空路径） | 扫描发现时 |
| 用户自定义 | 用户自建；**预置示例目录 `喜欢`**（可改名/删除） | 用户操作 |

规则：
1. **只在新记录首次创建时自动归类**；用户手动移动过 → 以用户选择为准，扫描/刷新**不覆盖**；
2. 改名《下载》等目录后，新下载的歌归入**改名后的目录**？—— 否：自动归类按**目录名匹配**（存在 `下载` 才归 `下载`，改名后新歌归"未分类"）还是按"记录来源"？→ **待确认（见 §6 第 2 点）**；
3. 用户删除系统目录（内置/下载）→ 该目录下歌曲归"未分类"，不删文件；
4. P2P 目录按用户名命名，用户改名后新收的歌仍按当前用户名 → 同名用户重名则合并且行（可接受）。

### 4.2 移动与批量的字段语义

- 移动 = 改 `path`；批量 = 多记录一次改；重命名 = 前缀替换（含子目录）；删除目录 = 其记录 `path` 置空；
- 目标目录不存在时自动创建（字段写入即存在）；
- 全部操作本地原子（全部成功或整体失败并提示），不落中间态。

### 4.3 边界

- **同步听歌**：自习室 DJ 驱动期间，本地集合不参与播放（跟随 DJ 唯一权威）；目录/标签浏览不受限；
- **内置歌曲**：不可改标签（沿用），可设目录归属；
- **外部删文件/手动放文件**：扫描后记录收敛（幽灵清理、新文件入未分类）；
- **PWA**：字段模型可全前端（localStorage/IndexedDB），桌面专属能力（时长/时间/扫描）降级缺省，其余功能照常。

## 5. 与 v2 的差异说明

1. 删除"播放队列(Queue)"概念 → 改为**集合(Set)**：列表无顺序职责、无序号、随机实时抽取；
2. 目录默认命名/自动归类规则落地（§4.1）；
3. 新增 F9 移动交互舒适性为 P0 核心需求；
4. 明确"表为唯一数据源，树/播放列表全为派生"的概念地基（§0）。

## 6. 剩余细节点（已确认，全部落定）

1. **自动归类锚点**：✅ 只在新记录首次创建时自动归类，用户移动过的歌永不被扫描覆盖。
2. **系统目录改名**：✅ **P0 默认目录（`内置`/`下载`/`{用户名}传输`）不可改名、不可删除**；
   新下载的歌永远进入 `下载`。未来放开"改名/绑定来源"（P2 候选）。
3. **预置 `喜欢` 目录**：✅ 预建且**不可删除**，具有特殊"一键标记"位（♥）；未来扩展"一键标记后选目录"。
4. **P2P 目录命名**：✅ `{用户名}传输`；用户改昵称后历史目录不自动迁移（P0 接受）。
5. **未分类节点**：✅ 保留特殊节点；未来"从本机导入"功能（`导入` 目录 / 以原文件夹名命名 两种方案）先写进规划，不在本期实现。
