## 二、数据库模型

### 核心表结构

| 表名 | 用途 |
|------|------|
| `study_rooms` | 房间信息（名称、密码、创建者、状态） |
| `room_members` | 成员信息（用户名、番茄数、学习时长） |
| `daily_room_records` | 每日学习统计（归档用） |

### 关键字段

**study_rooms 表：**
- `id`: 主键
- `room_code`: 房间号（唯一标识）
- `room_name`: 房间名称
- `password`: 房间密码（可为空）
- `is_active`: 是否活跃
- `created_by`: 创建者用户名
- `created_at`: 创建时间

**room_members 表：**
- `id`: 主键
- `room_id`: 关联房间
- `username`: 用户名
- `tomato_count`: 完成的番茄数
- `focus_duration`: 专注时长（秒）
- `join_time`: 加入时间
- `is_online`: 是否在线
- `last_heartbeat`: 最后心跳时间

## 三、核心功能流程

### 1. 创建房间

```
用户输入房间名/密码 → 检查房间号是否存在 
                   → 创建房间记录 
                   → 自动以创建者身份加入
```

**🎲 随机名称（v4.5.10 起，v4.5.11 扩充）**：房间名输入框旁新增 🎲 按钮，一键生成**与当前时间相关的有设计感的随机名**（可多次点击换新），来源 `src/utils/roomName.ts` 的 `generateRoomName()`：
- **时段意象**：按当前小时分 7 段、每段 6 个意象词（晨光/破晓/朝阳/微曦/初晴/启明、书页/启程/窗台/晨读/专注/青空、正午/日悬/暖阳/晌午/烈日/高照、午后/余晖/慢煮/茶歇/慵懒/暖窗、黄昏/暮色/归途/晚霞/落照/倦鸟、夜读/灯下/萤火/星夜/晚风/月下、静夜/星火/守夜/子时/深蓝/零点），名字与当下时间有关、不无意义；
- **学习名词池**：37 个（番茄/书桌/笔尖/心流/灯塔/岛屿/树洞/穹顶/花园/时光/窗棂/钟摆/砚台/灯芯/藤蔓/山径/溪谷/云影/屋檐/烛光/沙漏/钥匙/诗行/木屋/风铃/晨露/麦田/星图/炉火/纸船 + 桃花源/九重塔/千纸鹤/月亮船/时光机/萤火虫/忘忧草）；
- **格式**：`时段意象 + 名词 + 两位数编号`（10-99），组合空间约 14 万种，示例：`暮色书桌 23`、`夜读萤火 41`、`月下纸船 07`、`深蓝桃花源 52`。

**同步听歌"使用说明"（v4.5.11）**：同步听歌卡片新增可展开的 📖 使用说明（`syncInfoOpen` 折叠状态），未开启同步时也能先了解机制，重点告知用户：① 房间由 DJ 控制播放、其他人跟随；② 缺歌自动 P2P 传歌（边下边播/全员就绪统一播两种模式）；③ **开启同步即代表同意把本地歌曲共享给房间内缺歌的人**（仅房间内点对点传输，不上传公开服务器）；④ 下载的歌曲保存到本地音乐库并打上来源标签（DJ 名字），可随时删除。

### 2. 加入房间

```
输入房间号+密码 → 验证房间是否存在/密码正确 
               → 检查是否已在其他房间 
               → 添加成员记录
```

### 3. 学习数据同步

```
番茄钟完成 → 累加本地计数 → IPC 发送到主进程 
          → 更新本地数据库 
          → 同步到云端 Supabase
```

### 4. 实时数据更新

```
前端定时轮询(每5秒) → 获取房间所有成员最新数据 
                   → 刷新 UI 排行榜
```

## 七、心跳机制（已实现）

### 设计理念

采用**去中心化检测**方式：每个客户端心跳时都会检查所有房间和成员的状态，而不是依赖单独的清理进程。

### 心跳触发时机

| 时机 | 当前实现 | 说明 |
|------|----------|------|
| 进入房间 | ✅ 已实现 | `startHeartbeat()` 立即执行一次 |
| 退出房间 | ❌ 未实现 | 需要在离开前执行最后的心跳 |
| 定时心跳 | ✅ 已实现 | 每 5 分钟执行一次 |

### 心跳检查流程

```
updateOnlineStatus(roomId):
  1. 更新当前用户:
     - last_active = now
     - is_online = true
     
  2. 检查所有成员超时:
     - 获取所有自习室的所有成员
     - 如果 last_active > 11分钟 且 is_online = true
     - 批量更新为 is_online = false
     
  3. 检查空房间:
     - 获取所有 is_active = true 的房间
     - 如果房间无在线成员
     - 更新为 is_active = false
```

### 超时阈值

- **心跳间隔**：5 分钟
- **超时阈值**：11 分钟（心跳间隔 × 2 + 1分钟宽限）

### 相关 IPC 接口

```javascript
// 发送心跳并触发检查
window.electronAPI.studyRoomUpdateStatus(roomId)
```

## 十二、心跳机制（已完善）

### 设计理念

采用**去中心化检测**方式：每个客户端心跳时都会检查所有房间和成员的状态。

### 心跳触发时机

| 时机 | 状态 | 说明 |
|------|------|------|
| 进入房间 | ✅ | `startHeartbeat()` 立即执行一次 |
| 退出房间 | ✅ | 调用 `checkRoomStatus()` 检查房间状态 |
| 定时心跳 | ✅ | 每 5 分钟执行一次 |

### 心跳检查流程

**updateOnlineStatus（心跳）**：
1. 更新当前用户 `is_online = true`
2. 检查所有成员，超时（>11分钟）的标记离线
3. 检查空房间，标记 `is_active = false`

**checkRoomStatus（只检查）**：
1. 检查指定房间的成员超时
2. 检查房间是否需要下线
3. **不更新当前用户的在线状态**

### 超时阈值

- **心跳间隔**：5 分钟
- **超时阈值**：11 分钟

### 2. 房间权限模型（v4.4.1 起）

| 能力 | 说明 |
|------|------|
| 房主（owner_id） | 唯一创建者；可删除房间、切换公开/私密、设置/清除密码 |
| 公开房间 | 出现在 `GET /api/v1/rooms` 列表，任何人可加入（无密码） |
| 私密房间 | 不出现在公开列表，只能通过 ID 加入；可另设密码（ID+密码） |
| 密码规则 | 设置非空密码 → 自动转私密；设为公开 → 自动清空密码（服务器强制） |

### 3. 核心流程

**创建**：名称 + 描述 + 隐私（公开 / 私密 / 私密+密码）→ `room:create`（WS 请求-响应）
**加入（ID）**：先 `GET /rooms/:id` 查详情 → 若 `has_password` 则弹出密码输入 → `room:join` 带密码
**在线成员**：join 后服务器广播 `room:members`；客户端若尚未进入房间视图则暂存到
`pendingMembers`，进入后应用（修复"在线成员显示为空"）；`presence:update` 推送
`member_status` 实时更新专注状态
**房主管理**：公开/私密切换、密码设置 → `PUT /api/v1/rooms/:id`（仅房主 200，否则 403）
**删除**：`DELETE /api/v1/rooms/:id`（仅房主）

### 4. 同步听歌（v4.4.0 起）

- 音频本地播放，服务器仅转发控制动作 + `timestamp_server` 时间戳
- DJ 模式：`music:request_dj` → `music:dj_changed`（比对 `dj_user_id` 与当前用户判断身份）
- 听众端：收到 `music:state` 后 `position = position_ms + (Date.now() - timestamp_server)` 校准跟播
- 事件统一由 `MusicPlayer.vue` 监听 `ws-event` 转发到 `music.ts` 的 `handleSyncWsEvent`

### 5. 已知待办（服务器侧）

- 僵尸房间：公开列表会永久保留 DB 中的空房间，需服务器定时清理（11 分钟超时下线机制）
- 服务器每 30s 补发一次 `room:members` 作为成员状态校准
